# 02 - 数据采集

## 数据集演进

| 版本 | 内容 | 帧数 | 说明 |
|---|---|---|---|
| v1 | 40 集 | 10,000 | 初次录制（纸巾卷抓取-放置） |
| v2 | 15 集 | 5,625 | 补录：**夹取动作"贴住再夹，夹住停 1 秒"**，位置挪 3~5 个点 |
| v3 | 55 集 | 15,625 | v1 + v2 合并（`scripts/merge_datasets.py`） |

## 关键教训 1：语言指令（tasks.parquet）

**LeRobot 录制默认不写任务描述**——VLA 没有语言指令根本训不了。检查方法：

```bash
python -c "
import pandas as pd
from pathlib import Path
p = Path.home()/'.cache/huggingface/lerobot/oye-Li-bc/oye_tissue_20260815_133841/meta/tasks.parquet'
print(pd.read_parquet(p))   # 若 task 列为空 → 必须修复
"
```

修复（`scripts/fix_tasks_parquet.py`）后，task 口令在**训练和部署时必须一字不差**：

```
Pick up the tissue roll wrapped with orange-yellow tape on the wooden table and place it on the blue-purple area
```

## 关键教训 2：演示质量决定夹取质量

v1 模型部署时**悬空 1cm 夹不住**。排查发现（详见 05-实验记录）：演示数据中夹取瞬间本身就悬空（遥操作时机偏早）。**补录时演示刻意"贴住再夹、夹住停 1 秒"**，是修复的关键动作。

## 关键教训 3：数据集合并

LeRobot 无现成 merge 命令，用录制式 API 实现（`scripts/merge_datasets.py`）：

- `__getitem__` 返回的 dict 是 **reader 复用对象**，不能跨调用缓存引用（必须逐帧立即处理）
- 图像从 `float32 [0,1] CHW` 反归一化为 `uint8 HWC` 再写入（writer 期望 0-255）
- `save_episode` 后必须 `finalize()` 落盘 `meta/episodes` 元数据
- repo_id 需用 HF 上已存在的 repo 占位（`create` 会联网校验）
